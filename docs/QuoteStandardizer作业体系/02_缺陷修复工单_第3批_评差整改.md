## E1 显式配对表

**问题**：`load_local_df` 用供应商目录名模糊匹配本地文件，配不上记为 0 行（29 家）；`load_online_df` 用名称前 6 个字匹配线上包，存在错配风险。

**要求**：
1. 新建配对表 `codex/代码处理/QuoteStandardizer测试/评差配对表.xlsx`，每家一行：经办人、供应商目录、原始报价文件（可多个，含 sha256）、商务单图片、线上解析包（文件名 + sha256）、本地标准解析文件（文件名 + sha256）、配对方式（精确 / 人工确认）、备注。
2. 配对规则：先按完整供应商名精确匹配；匹配不到的**不做模糊猜测**，列入“待人工确认”清单交大脑；严禁按名称前若干字匹配。
3. 评差脚本只读配对表，不再自行搜索文件；配对表中缺失的项在评差结果中显示为“未配对”，不得计为 0 行。
4. 对线上包：记录包内每个 xlsx、每个 Sheet 的行数；包内存在多个 Sheet 时，写明每个 Sheet 的含义（物料明细 / 汇总 / 其他），只有物料明细计入行数。

**验收**：配对表覆盖 132 家；回报中列出全部“待人工确认”项；用配对表重跑后，青岛鼎信本地行数为 515。

## E2 评差脚本去自评

**问题**：`src_rows = local_rows`（第 120 行）；本地评定写死为 `"PASS"`。

**要求**：
- 评差的参照一律来自“真值”：有人工真值（E4）的条目用人工真值；没有人工真值的条目，结论只能写“线上与本地不一致（未裁决）”，**不得**判任何一方对错。
- 本地结果与线上结果**用同一套规则**分别对真值评差，各自给出 PASS/FAIL。
- 删除所有写死的 `"PASS"`。
- 输出中“原表有效行数”只在有人工真值时填写，否则留空并注明“未人工核实”。

**验收**：在无人工真值的情况下运行，报告中不出现任何“线上 FAIL / 本地 PASS”结论，只出现“一致 / 不一致（未裁决）”。

## E3 比对规则修正

| 项 | 要求 |
|---|---|
| 行对齐 | 先按“名称 + 型号/规格关键字 + 单价”做行对齐（允许顺序不同），对不齐的行单独列为“仅一方存在”，不得按行序号逐行比 |
| 单位 | 比较前归一（`㎡/m2/平方米→m²`、`米→m` 等，归一表写在代码常量中并列入回报）；只有归一后仍不同才算不符 |
| 单价 | 写明比较哪一列：以原件标注的价格口径为准（含税/不含税）；双方取的口径不同时判为“口径不同”，单列统计，不计为单价错误 |
| 规格 | 双方都把“厂家原始规格参数 + 规格参数 + 全部属性列”合并成规格文本后再比较；“整表规格留空”判定必须同时检查属性列 |
| 商务条款 | 先确认线上系统当初是否收到商务单图片（问用户或查线上包内容）；未收到的，E13 不计为解析缺陷，单列为“输入范围不同” |
| 证据 | 每条缺陷记录：原件位置（页/行）、真值、线上值、本地值、对齐依据 |

**验收**：用 5 个构造用例（顺序打乱、`㎡` vs `m²`、含税/不含税、规格只在属性列、多 Sheet 汇总）证明不再误报；回报贴出用例与结果。

## E6 指标重算

在 24 家真值子集上分别计算线上与本地：
- 整单合格率（零差异才合格），并给出 **95% 置信区间**（Wilson 区间，写明公式与样本量）；
- 字段级准确率：行（漏/多）、单价、单位、规格、商务条款各自的准确率；
- 缺陷分布：按缺陷码统计，只计裁决为“线上错 / 本地错”的项；
- 本地程序准确率：如果本地整单合格率显著低于 100%，在报告中明确“本地结果不能作为全量评差的基准”。

全量 132 家：**不得**直接用“线上 vs 本地”的差异推算线上合格率；如需外推，只能基于 24 家的裁决结果，并给出区间。

**验收**：指标表 + 计算脚本 + 原始数据，三者可复现（回报中给出命令）。
