# 04 · 自检与持续改进机制

系统要做到"错了自己能发现、发现了能改进"，靠四样东西：

1. **标准答案集**：已核实的事实；
2. **回归测试与质量门禁**：每次改动后自动比对，退步就拦下；
3. **程序运行时自检**：每次正式运行结束时，自己检查不变式；
4. **缺陷闭环**：每个确认的错误都变成一条永久的回归用例。

## 1. 三道防线

| 防线 | 何时运行 | 拦什么 |
|---|---|---|
| 程序运行时自检 | 每次运行 `main.py` 结束前 | 违反不变式的输出（价格与原表不符、存疑未标注、输出无法追溯等） |
| 回归测试 R1 | 每次改代码后、每次验证时 | 与标准答案集不符；指标比上一个已接受版本差 |
| 人工复核 | 每批验证；新样例接入时 | 前两道防线漏掉的错误；标准答案集本身的错误 |

**核心指标是“漏报数”**：程序的值错了，却没有任何待复核说明。漏报必须为 0；每出现一次漏报，都要新增一条自检规则，使同类错误下次能被程序自己标出来。

## 2. 标准答案集

### 2.1 位置与结构

```
codex/代码处理/QuoteStandardizer测试/标准答案集/
  S1_重庆望变/
    样例.json        元数据
    物料.csv         逐项事实
    商务条款.csv     商务单逐字段事实
    证据/            截图
    变更记录.md      每次修改的原因与证据
  S2_雨中情/ …
```

### 2.2 `样例.json`

```json
{
  "编号": "S1",
  "供应商": "重庆望变电气（集团）股份有限公司",

  "原件sha256": "<计算得到>",
  "类型": "PDF扫描件",
  "页数": 2,
  "表格类型": {"1": "矩阵式", "2": "矩阵式"},
  "商务单": "/Users/qianqianawodebaobei/Downloads/重庆望变-非标准报价单/报价说明20260918.png",
  "覆盖范围": "全部",
  "定稿日期": "2026-10-30",
  "答案集sha256": "<定稿后计算>"

```

### 2.3 `物料.csv` 列定义

| 列 | 说明 |
|---|---|
| 页 | 页码或 Sheet 名 |
| 表类型 | 清单 / 矩阵 |
| 行定位 | 清单：该页从上到下第几条物料（只数物料行）；矩阵：行标题原文（如 `1250`） |
| 列定位 | 矩阵：该页从左到右第几个价格列 + 列标题原文；清单：留空 |
| 名称原文 | 原件上的名称 |
| 规格原文 | 原件上的规格参数原文（逐字） |
| 单位 | 原件上的单位；原件没有则留空 |
| 单价 | 原件上的数字（逐位） |
| 行内地区 / 行内品牌 | 原件该行的地区、品牌列内容；没有则留空 |
| 可读性 | 清晰 / 模糊 / 公章遮挡 / 无法判定 |
| 证据 | 截图文件名（非“清晰”项必填） |
| 来源 | 执行者转录 / 大脑裁决 |
| 备注 | — |

“无法判定”的项保留在表中，单价填空，不计入准确率分母，但程序对它的输出**必须带待复核说明**，否则计为漏报。

### 2.4 修改规则
- 标准答案集定稿后，只有在“原件证据表明答案写错”时才能改；
- 修改流程：执行者提交证据截图 → 大脑裁决 → 修改 → 在 `变更记录.md` 写明 日期、项、旧值、新值、证据、裁决人 → 更新 `答案集sha256`；
- 严禁为了让回归通过而修改答案。

## 3. 指标

| 指标 | 定义 |
|---|---|
| 价格准确率 | 单价与答案逐位一致的条数 ÷ 可判定条数 |
| 漏报数 | 值错误（任何字段）且该条没有对应待复核说明的条数 |
| 编造数 | 答案为空、输出有值的字段数；以及 F7 判定为“无原文出处”且确认是模型编造的参数数 |
| 漏行数 / 多行数 | 答案有、输出无 / 输出有、答案无 |
| 字段准确率 | 单位、地区、品牌、名称原文（含于规格）的逐字段一致率 |
| 商务条款准确率 | 商务条款逐字段一致率（勾选状态必须完全一致） |
| 待复核误报率 | 标了待复核但所有字段都正确的条数 ÷ 标了待复核的条数 |
| 稳定性差异数 | 同一版本连跑两次，任一字段不同的条数 |
| 失败页数 | 识别失败、未产出结果的页数 |
| 成本 | 视觉调用次数、清洗调用次数、Jev 调用次数、总 token、总耗时 |

对齐规则：矩阵表按（页, 行标题, 列序号）对齐；清单表按（页, 物料序号）对齐，并用名称原文做一致性检查。对不齐的条目单独列为“对齐失败”，不得混算成价格错误。

## 4. 质量门禁

### 4.1 绝对门禁（任何一项不满足即不通过）
- 漏报数 = 0
- 编造数 = 0
- 漏行数 = 0，多行数 = 0
- 失败页数 = 0（F2 完成后；完成前单独报告）
- 程序崩溃 = 0
- 程序运行时自检（第 5 节）无“违反”项

### 4.2 不退步门禁（与上一个已接受版本比较）
- 价格准确率、字段准确率、商务条款准确率：不得下降；
- 待复核误报率：上升不超过 2 个百分点；
- 稳定性差异数：不得增加；
- 总耗时：增加不超过 20%（功能性工单可由大脑豁免，需在回报中说明）。

门禁阈值只能由大脑修改。每次被接受的版本，其指标写入 `codex/代码处理/QuoteStandardizer测试/指标趋势.csv`（日期、提交号、样例、全部指标），作为下一次的比较基线。

## 5. 程序运行时自检（第 2 批工单实现）

每次运行 `main.py` 结束前自动执行，结果写入输出工作簿新增的「运行自检」Sheet，并在日志中汇总：

| 检查 | 对应不变式 |
|---|---|
| 每条物料的市场价 = 其 `source_ref` 指向单元格中解析出的数字 | I1 |
| 字段为空时无默认值；所有推断字段都带说明 | I2、I3 |
| 每个带 `cell_issue` 的单元格，其产生的物料都带对应说明 | I4 |
| 每条物料都在「原表对账」中，且状态不为“原表无此行” | I5 |
| 原文为“键:值;”的规格，输出「厂家原始规格参数」与原文逐字一致 | I6 |
| 失败页/表都在对账中有记录 | I7 |

任何一项“违反”：该批输出视为不可用，日志打印违反清单，退出码为 3。

## 6. 缺陷闭环

```
发现 → 登记 → 复核 → 根因分类 → 工单 → 修复 → 新增回归用例 → 回归通过 → 关闭
```

| 步骤 | 负责 | 要求 |
|---|---|---|
| 发现 | 执行者 / 用户 | 附原件证据 |
| 登记 | 执行者 | 写入 `codex/代码处理/QuoteStandardizer测试/缺陷台账.xlsx`，编号 `QS-<年月日>-<序号>`，永不复用 |
| 复核 | 大脑 | 对照原件确认成立 / 不成立；不成立的写明理由后关闭 |
| 根因分类 | 大脑 | 识别 / 表格结构 / 清洗 / 规则 / 商务条款 / 输出 / 流程 / 标准答案 |
| 工单 | 大脑 | 写入下一批 `02_缺陷修复工单_第N批.md` |
| 修复 | 执行者 | 一单一提交 |
| 回归用例 | 执行者 | **必须有一个“修复前失败、修复后通过”的用例**（标准答案集条目或单元测试），在回报中贴出修复前后的运行结果 |
| 关闭 | 大脑 | 审核回报后关闭 |

**漏报专项**：每个漏报缺陷在修复时，除了修正结果，还必须新增一条程序自检或标记规则，使同类错误即使再次发生也会被标出来。

## 7. 周期复盘

每完成一批工单或一批正式材料验证后，大脑做一次复盘，产出：
- 本批指标与趋势（来自 `指标趋势.csv`）；
- 缺陷按根因分类的分布，找出重复出现的类型；
- 对执行过程的审查：证据是否齐全、有无编造或误判（上一轮出现过 5 条误判，其中 2 条原件内容无出处）；
- 下一批工单与路线图调整。

## 8. 对执行者自身的校验

为防止验证者出错：
- 大脑对每份新样例的“清晰”项随机抽查至少 10 项；抽查发现任何一项转录错误，该样例的标准答案集全部重新核对；
- 回报中每条“原件是 X”的结论都必须能用截图复查，大脑会抽查截图；
- 执行者在同一批中被发现编造原件内容，本批结果作废重做。
