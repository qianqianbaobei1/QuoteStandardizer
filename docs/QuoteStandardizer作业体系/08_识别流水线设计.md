# 08 · 识别流水线设计 v2（Gemini CLI 主读 + DeepSeek 核查）

> 作者：大脑（Claude）　日期：2026-10-30
> 用户决定：视觉识别只用 Gemini，且通过 CLI（`agy`）调用；DeepSeek 负责核查存疑之处；流程串行、并行结合，速度与质量兼顾。

## 1. 设计依据（实测数据）

测试对象：重庆望变报价单两页（2026-10-29 渲染的 300dpi 页面图），共 164 个价格格，答案已由大脑逐格对照原件核实。

### 1.1 Gemini CLI（`agy`，模型 Gemini 3.8 Flash）

| 输入图 | 思考档位 | 第 1 页 | 第 2 页 | 每页耗时 | 自报存疑 |
|---|---|---|---|---|---|
| 增强图（去红章 + gamma 1.8） | high | 53/53 | 111/111 | 280–390 秒 | 第 2 页 6 格，正好是公章压住的格子 |
| 增强图 | **low** | **53/53** | **111/111** | **18–20 秒** | 第 2 页 4 格（少标了 2 行公章格） |
| 原图 | high | 53/53 | **109/111** | 275–330 秒 | 8 格 |

- 原图即使用 high 档也会读错（5400→5100，210000→211000）：**增强图是必须的**。
- low 档准确率与 high 相同，速度快约 15 倍：**主读用 low**；high 只用于少量裁决。
- low 档自报存疑的覆盖面不如 high：**不能只靠模型自报**，必须有独立核查。
- CLI 可同时返回每行纵向位置 `row_y` 和每列横向位置 `col_x`（0–1000 比例），实测定位准确，可用于截取证据图。

### 1.2 DeepSeek 核查方式对比

| 方式 | 结果 | 结论 |
|---|---|---|
| 按坐标裁切单格、放大 3 倍后盲读（增强图、原图各 4 格） | **错 6/8**，且全部自称“确定” | 裁切丢失上下文，**禁止使用** |
| 整页增强图 + 指明“第几行、哪一列”定点提问（6 格 × 2 次） | **12/12 全对**，每次约 1.5 秒 | **采用** |

## 2. 流程总览

```
                        ┌──────────────── 文档级：多份文档并行（DOC_CONCURRENCY）
                        │
每份文档 ──┬─ T：商务单识别（与页面识别并行）
           │     Gemini low 读 ‖ DeepSeek 读 → 逐字段比对 → 不一致字段 DeepSeek 定点复问 → 仍不一致标待复核
           │
           └─ 每页（页面级并行，受 AGY_CONCURRENCY 限制）
                 ① 预处理：渲染 300dpi → 原图 + 增强图；估计行数，超阈值则按行切块
                 ② 双读（并行）：
                      R1 = Gemini CLI low × 增强图（含 row_y / col_x / uncertain）
                      R2 = Gemini CLI low × 原图
                 ③ 比对（串行）：逐格对齐 R1、R2，生成“存疑格集合 D”
                 ④ 核查（串行，一次请求）：DeepSeek × 整页增强图，对 D 中所有格定点提问；
                      同时附带“哨兵格”抽检
                 ⑤ 裁决（串行）：多数一致规则（见第 4 节）
                 ⑥ 升级（仅未决格，少量）：Gemini CLI high × 增强图 定点提问 → 再裁决
                 ⑦ 仍未决：取 R1 值，标“待人工复核”，按坐标导出证据截图
                 ⑧ 该页完成后立即进入后续解析与清洗（流式，不等其他页）
           │
           └─ 全部页完成 → 对账 → 运行时自检 → 输出
```

## 3. 存疑格集合 D 的来源

一格只要满足任一条件，就进入 D：

| 来源 | 说明 |
|---|---|
| 双读不一致 | R1 与 R2 的值在 NFKC 归一、去空白、去千分位后仍不同 |
| 模型自报 | R1 或 R2 的 `uncertain` 中列出了该格 |
| 结构异常 | R1、R2 行数或列数不同时，无法对齐的行整行进入 D |
| 规则异常 | 价格列中非数字；矩阵表中“档位越高价格越低”；数字位数与同列其他值差异悬殊（如同列都是 5–6 位，此格 3 位） |
| 哨兵抽检 | 每页从“两读一致且无自报”的价格格中随机抽 `SENTINEL_PER_PAGE` 个（默认 8 个），一起交给 DeepSeek 核查 |

哨兵是**自我发现错误**的关键：两次 Gemini 读法可能错得一样，哨兵用于发现这种系统性错误。

## 4. 裁决规则

每个存疑格最多有 4 个读数：R1（Gemini 增强图）、R2（Gemini 原图）、D（DeepSeek 整页定点）、H（Gemini high 定点，仅升级时）。

| 情形 | 处理 | 输出标注 |
|---|---|---|
| R1 = R2 = D | 采用 | 无（自报存疑格保留“已核查一致”审计记录） |
| R1 ≠ R2，D 与其中之一相同 | 采用与 D 相同的值 | 待复核说明：“两读不一致（R1=… R2=…），经 DeepSeek 核查采用 …” |
| R1 = R2，但 D 不同 | **升级 ⑥** | — |
| D 是第三个值 / D 回答含 `?` | **升级 ⑥** | — |
| 升级后，H 与 R1、R2、D 中任意一个相同，形成至少两票一致 | 采用得票值 | 待复核说明写明各读数与采用理由 |
| 升级后仍无两票一致 | 取 R1 值 | **“待人工复核：读数分歧 R1=… R2=… D=… H=…”**，导出证据截图 |
| **哨兵格**中出现任何 D 与 R1 不一致 | 该格按上表处理；**并且该页全部价格格**再做一次 DeepSeek 整页定点核查 | 页面级审计记录“哨兵触发全页核查” |

原则：
- 采用值必须至少有两个独立读数一致；
- 任何经过裁决的格子都在输出中留痕，不得静默修改；
- 价格只取识别结果，模型推断、计算出来的值一律不得采用。

## 5. 并发与性能

| 层级 | 方式 | 配置项（默认） |
|---|---|---|
| 文档 | 多份文档并行 | `DOC_CONCURRENCY=2` |
| 页面 | 页面并行；R1、R2 同时发出 | `AGY_CONCURRENCY=4`（同时运行的 agy 进程数上限） |
| 核查 | 每页一次 DeepSeek 请求，覆盖该页全部存疑格与哨兵格 | `DEEPSEEK_CONCURRENCY=8` |
| 升级 | 仅未决格，按页合并成一次 high 请求 | `ESCALATE_EFFORT=high` |
| 清洗 | 页面完成即进入清洗（流式） | 沿用现有并发 |
| 缓存 | 按（页面图 sha256、模型、档位、提示词版本）缓存识别结果；稳定性测试时关闭 | `VISION_CACHE=1` |

估算（以实测为基础）：单页 ≈ 双读 20–30 秒 + 核查 2–5 秒；升级页额外约 5 分钟（预计少数）。13 页文档在 `AGY_CONCURRENCY=4` 下约 2–3 分钟。

## 6. Gemini CLI 调用规范（安全与稳定）

| 要求 | 说明 |
|---|---|
| 命令 | `agy -p <提示词> --model gemini-3.8-flash-<档位> --output-format json --json-schema <schema> --sandbox --add-dir <临时目录> --print-timeout <秒>` |
| 隔离 | 每次调用新建临时目录，**只放这一张页面图**；`--add-dir` 只指向该目录；调用结束后移到废纸篓或删除临时文件 |
| 只读 | 提示词开头明确“只读取图片，不执行命令、不修改或创建文件”；**严禁** `--dangerously-skip-permissions` |
| 结果校验 | 外层 JSON 的 `status` 必须为 `SUCCESS`；`response` 必须通过 schema 校验；`row_y` 长度等于行数；否则视为失败，重试 `LLM_MAX_RETRIES` 次 |
| 超时 | `--print-timeout` 之外再加进程级超时，超时强制结束进程 |
| 账号 | 不读取、不修改 `~/.agy-accounts` 与任何 OAuth 文件；账号切换沿用用户现有的 agy 账号机制；遇到额度/限流错误时退避重试，并在日志中记录 |
| 可配置 | `AGY_BIN`（默认 `~/.local/bin/agy`）、`AGY_MODEL_PRIMARY=gemini-3.8-flash-low`、`AGY_MODEL_ESCALATE=gemini-3.8-flash-high` |
| 记录 | 每次调用记录：模型、档位、耗时、`conversation_id`、`usage`；写入输出工作簿新增的「识别审计」Sheet |

## 7. 输出新增内容

- **「识别审计」Sheet**：每个存疑格一行：页、行标题、列标题、R1、R2、D、H、采用值、裁决规则、证据截图路径。
- **证据截图**：所有“待人工复核”的格子，用 `row_y`/`col_x` 从 300dpi 增强图和原图各截一张（含上下相邻行），存入 `<供应商>_图片库/证据/`。
- **页面级统计**：每页存疑格数、自动裁决数、升级数、未决数、哨兵触发与否、各阶段耗时。
