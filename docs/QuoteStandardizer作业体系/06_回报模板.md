# 06 · 回报模板

每完成一张工单或一次验证，在运行目录下写 `回报.md`，严格按下面的结构。缺项要写“无”，不能省略标题。

```markdown
# 回报：<工单编号或验证批次>

## 1. 基本信息
- 执行者：Gemini
- 时间：<开始> – <结束>
- 代码版本：修改前 <提交号> → 修改后 <提交号>（验证任务只写一个）
- 运行目录：<路径>
- 解释器：<路径>
- 配置：已配置的项名 <列表>；STRUCTURE_ENGINE=<值>
- 并发情况：执行期间 QuoteStandardizer/ 是否被其他程序改动：<是/否>

## 2. 做了什么
- 改动的文件与函数：<逐条>
- 与工单要求的对应关系：<工单的每条实现要求 → 对应的改动>
- 工单范围以外的改动：<无 / 逐条说明并说明为什么>

## 3. 验收结果
| 验收项（照抄工单） | 结果 | 证据（文件路径 / 运行结果摘录） |
|---|---|---|

## 4. 回归结果
- 命令：<完整命令>
- 门禁：通过 / 不通过
- 指标对比（与上一个已接受版本）：
  | 样例 | 指标 | 基线 | 本次 | 变化 |
  |---|---|---|---|---|
- 修复前失败、修复后通过的用例：<用例名 + 修复前输出 + 修复后输出>

## 5. 发现的问题
| 编号 | 样例 | 位置（页/行标题/列，报价ID，source_ref） | 原件内容 + 截图 | 程序输出（从文件复制） | 是否已标待复核（摘录原文） | 判定 | 严重度 |
|---|---|---|---|---|---|---|---|

## 6. 需要大脑决定的事项
- <逐条；没有写“无”>

## 7. 自查
- [ ] 每条“原件是 X”都附了能看清 X 的截图，且我已打开截图确认
- [ ] 引用的程序输出都写明了文件、报价ID、source_ref，值是从文件复制的
- [ ] “是否已标待复核”都摘录了「报价说明」原文
- [ ] 没有修改标准答案集 / 门禁阈值 / .env
- [ ] 没有删除文件；需要清理的已移到 ~/.Trash/ 并在此列出
- [ ] 一张工单一个提交，没有夹带改动
```

严重度定义：
- **P0**：漏报（值错且未标记）、编造、漏行、多行、崩溃、运行时自检违反
- **P1**：已标记的错误值；商务条款错误；供应商/品牌/单位/地区错误
- **P2**：措辞或写法与原件不一致但不影响含义；稳定性差异
- **P3**：误报、提示文字不准确、日志/报告问题
