## 1. 目标

把厂家的非标准报价单（Excel / PDF / 图片）解析成统一格式的报价表，并做到三点：

1. **对的就是对的，错的就是错的。** 唯一的事实来源是报价原件；程序输出、人工整理的参考文件、模型自报的置信度，都不预设为正确。
2. **错了自己能发现。** 每一个错误都要么被程序自己标出来，要么被回归测试拦下来；不允许"错了但没人知道"。
3. **发现了就能改进。** 每个已确认的错误都要变成一条回归用例，以后不会再犯同样的错。

## 2. 角色与分工

| 角色 | 职责 | 不做什么 |
|---|---|---|
| **用户** | 提供正式材料；做业务决策（输出规范、数据能否外发、是否上线） | — |
| **大脑（Claude）** | 定架构与标准；写工单和验证任务；审核执行者的回报；裁决争议；决定下一步 | 不直接执行批量任务 |
| **执行者（Gemini）** | 按工单改代码、跑测试、做原件核对、按模板回报 | 不自行改需求、不自行扩大改动范围、不自行判定"标准答案" |

执行者遇到以下情况必须**停下来回报，等大脑答复**，不能自行决定：
- 工单描述与代码现状对不上；
- 修一个问题需要改动工单范围以外的文件或行为；
- 原件上的内容看不清，又影响验收结论；
- 任何会删除文件、覆盖输出、改动 `.env`、改动标准答案集的操作。

```
     └──────── 大脑审核：通过 / 打回（附具体原因）←─────────────┘
```

## 5. 红线（违反任何一条，本轮结果作废）

1. **不编造原件内容。** 回报中写"原件是 X"时，必须附上能看清 X 的放大截图路径；截图里看不清，就写"原件无法判定"，并说明原因（公章遮挡 / 褪色 / 分辨率不足）。上一轮出现过把公章文字写成原件上根本没有的公司名，这类错误不能再出现。
2. **不凭记忆引用程序输出。** 写"程序输出是 Y"时，必须写明输出文件路径、报价ID、原表位置（`source_ref`），并且是从文件中复制的值。
3. **"已标记 / 未标记待复核"必须查证。** 结论前打开该行的「报价说明」列，原样摘录相关文字。
4. **测试期间代码冻结。** 开始任何测试前记录 git 提交号；测试期间任何人不得改动 `QuoteStandardizer/`。发现代码被改动（提交号或文件修改时间变化），立即停止并回报。
5. **一张工单一个提交。** 不夹带工单以外的改动；不"顺手优化"。
6. **不改标准答案集来让测试通过。** 标准答案集只能按 `04` 中的争议流程修改，并留下原件证据。
7. **不降低门禁来让测试通过。** 门禁阈值只能由大脑修改。
8. **不泄露密钥。** 不打印、不复制 `.env` 中任何 Key 的值；需要时只说"已配置 / 未配置"。
9. **不删除文件。** 需要清理时移到 `~/.Trash/`，并在回报中列出。
10. **路径规范。** 不在 `PycharmProjects/` 根目录下创建任何东西；产出只放在 `codex/` 下的规定位置。
