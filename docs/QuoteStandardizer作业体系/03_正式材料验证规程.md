# 03 · 正式材料验证规程

> 用途：用用户提供的真实报价单，判断系统输出是否可用。
> 取代：`codex/日常办公/QuoteStandardizer测试计划.md`（作废）。

## 1. 原则

1. **原件是唯一事实来源。** 程序输出、参考文件、模型置信度、本规程执行者自己的记忆，都不是证据。
2. **证据先于结论。** 每一条"原件是 X"都必须附上能看清 X 的截图；没有截图的结论无效。
3. **先独立转录，再看程序输出。** 防止被程序结果带偏。
4. **看不清就说看不清。** "原件无法判定"是合法结论，猜测不是。
5. **版本冻结。** 验证期间代码不变；结论只对记录的那个 git 提交有效。

## 2. 流程总览

| 阶段 | 名称 | 产出 |
|---|---|---|
| V0 | 开工与冻结 | 运行目录、提交号、环境记录 |
| V1 | 样例登记 | 样例登记表 |
| V2 | 原件独立转录 | 标准答案集草稿 + 证据截图 |
| V3 | 争议裁决 | 标准答案集定稿（经大脑确认） |
| V4 | 程序运行 | 输出文件 + 运行日志（每份样例 2 次） |
| V5 | 自动比对 | R1 回归报告 |
| V6 | 人工复核 | 差异逐条判定 + 抽查记录 |
| V7 | 结论与回报 | `回报.md` |

## 3. 各阶段要求

### V0 开工与冻结
- 执行 `00_总纲.md` 第 6 节的开工检查清单。
- 记录：git 提交号、Python 路径、`.env` 中已配置的项名（不写值）、`STRUCTURE_ENGINE` 取值。
- 视觉探针：生成一张含已知 6 位数字的图片，确认视觉模型读对；读错则停止，回报"阻塞"。

### V1 样例登记
每份样例登记以下信息，写入 `样例登记表.xlsx`：
- 编号、供应商、原件路径、文件类型（Excel / PDF 文字层 / PDF 扫描件 / 图片）、页数或 Sheet 数；
- 表格类型（清单式 / 矩阵式 / 混合）、是否旋转、是否有公章覆盖表格、是否跨页续表；
- 商务单图片路径（多个内容相同的图片要注明）；参考文件路径（如有，注明“不预设正确”）。

### V2 原件独立转录
- 把每页渲染成 300dpi 全页图（存 `<样例>/原件高清图/`）；数字看不清时再局部渲染到 600–1200dpi，并做一份去红章版本对照。
- 按 `04` 第 2 节的标准答案格式逐项转录：
  - 清单式：每行物料的名称、规格原文、单位、单价、行内地区、行内品牌等全部列；
  - 矩阵式：每个有价格的交叉格（行标题 × 列标题 → 价格），以及空格数量；
  - 商务单：每个字段的原文；勾选框逐个记录选中/未选中。
- 每项标注可读性；非“清晰”项必须有截图，截图文件名写入该项的 `证据` 列。
- **截图自检**：每张截图打开确认，目标数字/文字确实在画面中且可辨认；截错位置的重截。

### V3 争议裁决
- 把所有“模糊 / 公章遮挡 / 无法判定”项列成清单，连同截图交给大脑；
- 大脑给出裁决（确认值 / 维持无法判定），执行者照此写入标准答案集，`来源` 列写“大脑裁决”；
- 标准答案集定稿后，计算并记录其文件哈希。

### V4 程序运行
- 每份样例运行 2 次（`第1次`、`第2次`），输出到运行目录；记录退出码、耗时、日志中的 Warning/Error。
- 如需评估 Jev 试点，额外运行一次 `STRUCTURE_ENGINE=compare`（见 3.1）。

### V5 自动比对
```bash
$PY codex/代码处理/QuoteStandardizer测试/regress.py --gt-dir <标准答案集目录> --outputs <运行目录> --repeat 2
```
实际参数以 `python3 regress.py --help` 为准：`--gt-dir`（标准答案集，默认内置 GT_DIR）、`--samples`、`--outputs`、`--repeat`、`--run-dir`。**原文写的 `--golden` 在实际脚本中不存在，照抄会直接报 `unrecognized arguments`。**
- 门禁不通过时，不要“调整”任何东西让它通过，直接进入 V6 分析原因。

### V6 人工复核
- **每一条差异**都要回到原件判定，结论只能是：
  `程序错` / `标准答案错（附证据，走 V3 修订）` / `两者都对（口径不同，写明差别）` / `原件无法判定`。
- 对每条“程序错”，记录：是否已被程序标记待复核（原样摘录「报价说明」中的文字）。
- **一致项抽查**：每份样例随机抽取不少于 20 条（不足 20 条全查），确认确实一致。随机方式写进回报（例如固定随机种子）。
- 引用程序输出时，写明：输出文件、报价ID、原表位置（`source_ref`），值从文件中复制。

### V7 结论与回报
按 `06_回报模板.md` 填写。每份样例给出可用性结论：

| 结论 | 条件 |
|---|---|
| **可直接使用** | 价格准确率 100%（可判定部分）；漏报 0；编造 0；漏行 0；多行 0 |
| **复核后可用** | 漏报 0、编造 0、漏行 0，但有已标记的错误或缺失字段（列出需人工处理的条目） |
| **不可用** | 有任何漏报、编造、漏行；或程序未能产出结果 |

### 3.1 Jev 试点对比（可选任务）
- 运行 `STRUCTURE_ENGINE=compare`（注：**当前 compare 与 gemini 走同一条链路，尚未产出对比表**，需人工从控制台的 `! 表格类型判定分歧` / `Jev 行类型判定` 日志取分歧项）；
- 每个分歧项对照原件判定：`现有做法对` / `Jev 对` / `两者都对（口径不同）` / `两者都错` / `原件无法判定`，记入本规程归档表；
- 一致项抽查不少于 20 项；
- 统计 Jev 置信度 < `JEV_MIN_CONFIDENCE` 的项中判对/判错的数量；记录 Jev 请求次数与 token 用量。

## 4. 证据规范

| 要求 | 说明 |
|---|---|
| 截图位置 | `<运行目录>/<样例>/证据/` |
| 命名 | `<样例>_p<页>_<行标题或行号>_<列名>_<dpi>.png`，例如 `S1_p2_1250kVA_SCB12_1200dpi.png` |
| 内容 | 必须包含目标格及其相邻至少一格（便于定位）；公章遮挡时同时给原图和去红章图 |
| 引用 | 回报和缺陷清单中用完整路径引用 |

## 5. 新样例接入
用户提供新的正式材料时：
1. 原件放在用户指定位置，执行者只读不改；
2. 走 V1–V3 建立该样例的标准答案；
3. 定稿后加入标准答案集，从此纳入每次回归。
