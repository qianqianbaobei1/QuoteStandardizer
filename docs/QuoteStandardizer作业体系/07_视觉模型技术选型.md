## 1. 结论（2026-10-30 更新：用户决定只用 Gemini，且通过 CLI 调用）

| 角色 | 选型 | 依据 |
|---|---|---|
| **主读** | Gemini 3.8 Flash，经 Antigravity CLI（`agy`）调用，**low 档**，增强图 | 望变 164/164 全对，每页 18–20 秒（high 档同样全对但需 280–390 秒） |
| **复读** | 同上，low 档，原图 | 输入不同，用于发现不一致；原图单独使用准确率较低（high 档 109/111），只作比对不作采用依据 |
| **核查** | DeepSeek `deepseek-chat`，整页增强图 + 定点提问 | 公章/褪色难格 12/12 全对，每次约 1.5 秒 |
| **裁决升级** | Gemini 3.8 Flash high 档，定点提问 | 仅用于少数未决格 |
| 结构化清洗 | DeepSeek（不变） | — |
| 不采用 | 通义千问（用户决定）；Gemini API 直连（本机不可用，见第 2 节）；本地 Tesseract（准确率约 32%）；DeepSeek 裁切单格核查（实测错 6/8） | — |

完整流程见 `08_识别流水线设计.md`。以上数据只来自一份样例、每种配置各跑一次，正式采用前仍需按第 2 批工单在新样例库上做基准验证。

**不允许凭模型名气选型。** 任何模型进入默认链路，都必须在标准答案集上通过 P5 基准验证，且不比现有组合差。

## 2. Google 视觉模型现状（实测）

| 检查 | 结果 |
|---|---|
| AI Studio 接口（`generativelanguage.googleapis.com`） | `400 FAILED_PRECONDITION: User location is not supported for the API use.` 所在地区不支持 |
| 当前 Key 格式 | `AQ.` 开头，为 **Vertex AI 快速模式** Key，不是 AI Studio Key |
| Vertex AI（`vertexai=True`） | `403 PERMISSION_DENIED`：所属 Google Cloud 项目未启用相应 API |
| 测试过的模型名 | `gemini-3.8-flash`、`gemini-3-flash-preview`、`gemini-3-pro-preview`、`gemini-2.5-flash`、`gemini-2.5-pro`、`gemini-2.5-flash-lite`：全部不可调用 |

因此：
- 当前默认 `EXTRACTOR_ENGINE=gemini` 时，每次处理 PDF 都会先调用 Google，重试失败后**静默**退回 DeepSeek，输出中不记录实际走了哪条链路；
- 执行者报告中的“Gemini B 轨测试”实际全部由 DeepSeek 完成；
- 模型名 `gemini-3.8-flash` 是否真实存在，未能验证。

要使用 Gemini，需要用户先解决两件事：
1. **访问路径**：在 Google Cloud 项目中启用 Vertex AI 相关 API 并开通计费，或改用受支持地区的网络/账号；
2. **数据合规**：报价单会被发送到境外服务，需用户确认允许。

## 3. 选型标准

| 维度 | 权重 | 说明 |
|---|---|---|
| 价格识别准确率 | 最高 | 标准答案集上逐格比对；**漏报（错了且没被标出）必须为 0** |
| 自报存疑的有效性 | 高 | 模型标“看不清/公章遮挡”的格子，是否覆盖了它读错的格子 |
| 大页面能力 | 高 | 约 90 行的页面是否截断；切块后是否稳定 |
| 与主模型的独立性 | 高 | 交叉校验要求“错法不同”：同一模型读两遍，错法往往相同（望变第 1 页 2500kVA×S20 原图读成 100000 的错误就是例子） |
| 可用性与合规 | 门槛 | 在本机网络可稳定调用；数据可发送 |
| 延迟、成本 | 中 | 每页耗时、每页费用 |
| 结构化输出 | 中 | 是否稳定输出合法 JSON |

## 4. 当前 Gemini B 轨的设计问题（即使能调通也不能直接用）

| 问题 | 后果 |
|---|---|
| 整份 PDF 一次请求、一次输出 | 多页密集表格必然超出输出上限，被截断；与 F2 要解决的问题相同 |
| 没有双读交叉校验 | 失去目前最有效的错误发现手段 |
| 没有增强图（去红章、压暗褪色笔画） | 褪色数字、公章遮挡处的识别没有保障 |
| 提示词示例里写死了“重庆望变”“S13型（NX3）”“1000公里以内含运费” | 违反 I9；示例文字可能被模型抄进输出 |
| 按返回顺序编页码，不核对 `page_number` 和总页数 | 模型漏掉一页时，后面的页码全部错位 |
| 把页面标题和备注作为行写进表格 | 污染表格，可能被当成表头或物料行 |
| `interactions` 返回取不到 `output_text` 时用 `str(interaction)` 兜底 | 会把对象的描述字符串当成 JSON 去解析 |
| REST 兜底把 Key 放在 URL 里 | Key 可能出现在日志中 |
| 默认引擎改为 `gemini` | 违反 I8（默认行为未经批准改变） |

**正确的接入方式**：不要另起一条整文档链路，而是把 Gemini（或任何新模型）作为现有逐页流水线中的**一个读者**接入：沿用增强图、切块、逐格比对、存疑标注，只是把“第二遍”或“第一遍”换成这个模型。这样所有安全机制自动生效，选型也只是换一个配置项。

## 5. 推荐方案

1. **立即**：默认链路恢复为现有 DeepSeek 逐页流水线（工单 B1），停止调用不可用的 Gemini API。
2. **实现**：按 `08_识别流水线设计.md` 实现“Gemini CLI 双读 + DeepSeek 核查 + 分歧升级”流水线（工单 P1–P5），以开关 `RECOGNITION_PIPELINE=v2` 启用。
3. **验证**：在新样例库的标准答案集上，比较 v2 与现有链路的准确率、漏报、耗时；v2 不劣于现有链路且漏报为 0，才由大脑批准设为默认。
