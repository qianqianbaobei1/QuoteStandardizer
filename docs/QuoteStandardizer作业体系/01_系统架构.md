# 01 · 系统架构

## 1. 数据流

```
原件 (.xlsx / .pdf / 图片)
  │
  ├─ Excel ──→ extractor.py：展开合并单元格、公式取缓存值、图片定位
  ├─ PDF 文字层 ──→ pdf_extractor.py：PyMuPDF find_tables
  └─ 扫描件 ──→ pdf_extractor.py：视觉模型逐格转录
                  · 第一遍：增强图 (去红章、gamma 压暗褪色笔画)，以此为准
                  · 第二遍：原图，逐格比对，不一致 → cell_issue
                  · 模型自报看不清 / 公章遮挡 → cell_issue
  │
  ▼  统一成「表格」(openpyxl Worksheet)，每格可附 cell_issue
  │
main.py · standardize_workbook
  ├─ 判定表格类型：矩阵式 (_detect_matrix) / 清单式
  ├─ 清单式：表头行、单价列、单位列 (llm_agent 或 Jev)；逐行判定行类型
  ├─ 矩阵式：行标题 × 列标题展开；同列名称统一；单调性校验
  ├─ 清洗：llm_agent.DeepSeekStandardizer → 名称、结构化参数、单位
  │        原文是 “键:值;” 的参数原样保留
  ├─ 商务条款：terms_extractor (视觉模型识别商务单 或 --terms-json)
  │        公章识别的供应商需与文件名/表格内容互证 (verify_terms_supplier)
  └─ 每条物料：价格只取原表；问题写入 uncertainty_note
  │
  ▼
models.reconcile：原表 ↔ 输出逐行对账
  │
  ▼
builder.py：「标准化报价」「疑义与失败审计说明」「原表对账」「结构判定对比」(试点)
```

## 2. 模块职责

| 文件 | 职责 | 对外接口 |
|---|---|---|
| `main.py` | 入口、主流程、行/列解析、供应商推导、对账调度 | `process_excel` / `process_pdf` / `standardize_workbook` |
| `extractor.py` | Excel 合并单元格展开、数值精度、图片锚点 | `unmerge_and_fill_cells`、`cell_str`、`ExcelAssetExtractor` |
| `pdf_extractor.py` | PDF → 表格；视觉转录与双读校验 | `PDFTableExtractor.to_workbook()`、`cell_issue`、`page_titles` |
| `llm_agent.py` | DeepSeek 表头推导与物料清洗；Jev 选择题判定 | `DeepSeekStandardizer`、`JevJudge` |
| `terms_extractor.py` | 商务单识别与规范化 | `TermsExtractor`、`normalize_terms`、`find_terms_image` |
| `models.py` | 物料记录、对账 | `CanonicalMaterialItem`、`SourceRowRecord`、`reconcile` |
| `builder.py` | 输出工作簿 | `StandardizedWorkbookBuilder` |
| `config.py` | 环境配置、省份映射、编码库加载 | 常量与 `resolve_category_code`、`expand_region` |

## 3. 不变式（任何改动都不得破坏）

改代码前逐条确认；回归测试中每条都有对应检查（见 `04`）。

| 编号 | 不变式 |
|---|---|
| I1 | **价格只取原表。** 输出的「市场价」必须等于原表（或转录表）单元格中的数字；模型返回的价格只能用于比对。 |
| I2 | **不知道就留空。** 原件没有的信息不得填写默认值（单位、税率、地区、折扣、编码、品牌等）。 |
| I3 | **推断要标明。** 由推断得出的字段（品牌由公司名推断、供应商由文件名推断、编码未经编码库核验等）必须写入待复核说明。 |
| I4 | **存疑要标明。** 带 `cell_issue` 的单元格所产生的物料，必须在待复核说明中出现对应原因。 |
| I5 | **每条输出都能追溯。** 每条物料都有 `source_ref`，并在「原表对账」中出现。 |
| I6 | **原文写法不改。** 原文已是“键:值;”的规格原样保留；单位、用字、符号不替换。 |
| I7 | **失败要显式。** 某页、某表失败时，结果中要写明失败的页/表和原因；不得静默跳过，也不得让一页失败导致整个文件没有结果。 |
| I8 | **默认行为不变。** 新功能必须通过开关启用（如 `STRUCTURE_ENGINE`），未经大脑批准不得改变默认输出。 |
| I9 | **无硬编码。** 不写个人路径、不写只对某个样例成立的规则、不内置未经核实的编码或业务数据。 |

## 4. 配置项（`.env`）

| 项 | 作用 | 默认 |
|---|---|---|
| `DEEPSEEK_API_KEY` / `_BASE_URL` / `_MODEL` | 清洗与视觉识别 | `deepseek-chat` |
| `VISION_*` | 改用其他视觉模型 | 同 DeepSeek |
| `VISION_DOUBLE_CHECK` | 扫描件双读 | `1` |
| `VISION_GAMMA` | 增强图压暗程度 | `1.8` |
| `TEMPLATE_PATH` | 输出模板 | 内置 33 列 |
| `CATEGORY_CODE_FILE` | 标准分类编码库 | 无 (编码留空) |
| `STRUCTURE_ENGINE` | `llm` / `jev` / `compare` | `llm` |
| `TYPESAFE_API_KEY` | Jev | — |
| `JEV_MIN_CONFIDENCE` | Jev 低置信度阈值 | `0.5` |

## 5. 已知限制（截至第 1 批工单前）

- 不支持单张图片报价单（工单 F1）。
- 大页面（约 90 行以上）转录不稳定，输出过长会导致整个程序崩溃（工单 F2）。
- 表头叫“报价城市”等名称时，识别不到报价地区列（工单 F3）。
- 表内品牌列被忽略（工单 F4）。
- 矩阵表的列标题转录两次结果不同，导致名称、参数不稳定（工单 F5）。
- 双读把只差全角/半角的情况算作不一致（工单 F6）。
- 结构化参数没有逐项核对原文出处（工单 F7）。
- 跨页续表（表头只在第 1 页）未处理（路线图 P2）。
- 公章文字识别很不可靠，只能依靠旁证互证。
