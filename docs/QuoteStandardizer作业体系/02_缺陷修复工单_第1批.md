## R1 回归测试工具

**位置**：`codex/代码处理/QuoteStandardizer测试/regress.py`

**功能**：
1. 读取标准答案集目录（`04` 第 2 节格式）。

## F2 大页面切块识别与失败隔离（原 D010）

**现象**：骊丞汇第 1 页（92 行）两遍识别有 170 格不一致、42 行对不上；第 2 页模型输出被截断（`Unterminated string … column 14156`），抛出异常，整个文件没有任何输出。

**改动范围**：`pdf_extractor.py`、`main.py`（失败页汇总）、`models.py`/`builder.py`（失败页写入对账）。

**实现要求**：
1. **截断检测**：视觉调用返回 `finish_reason == "length"`、或 JSON 解析失败时，视为“输出过长”。
2. **切块重试**：输出过长、或页面行数估计超过阈值（可配置，默认 40 行）时，把页面图片按水平方向切成若干条带，相邻条带重叠至少 1 行；每个条带单独转录。
   - 每个条带的提示词中给出第 1 个条带识别出的表头和列数，要求输出相同列数；
   - 合并时去掉重叠区重复的行（按整行内容匹配），并检查列数一致；列数不一致的条带整体标记 `cell_issue`；
   - 双读校验按条带分别进行。
3. **失败隔离**：某页在切块重试后仍失败时，不抛异常中断，而是：
   - 该页在「原表对账」中写一行 `异常:第N页识别失败（原因）`；
   - 继续处理其余页；
   - 运行结束时打印失败页清单，退出码为 2（部分成功）。
4. 新增配置项写入 `config.py` 与 README：`VISION_MAX_ROWS_PER_TILE`、`VISION_TILE_OVERLAP_ROWS`。

**验收**：
- S5 全部 13 页都有输出，不崩溃；退出码 0（若仍有失败页，则为 2，且失败页在对账中可见）。
- S5 已有标准答案的页（1、2、13）：价格门禁通过。
- S5 每页双读不一致格数占比 ≤ 5%；超过的页在回报中单独列出原因。
- 人为让一页失败（例如单元测试中模拟视觉调用异常），其余页照常输出，对账中出现该页失败记录。
- S1–S3 回归结果与基线相同。

## F5 矩阵表列标题与命名稳定（原 T11 / D002）

**现象**：望变连跑两次，价格完全相同，但「名称规格」38 条、「规格参数」102 条、「厂家原始规格参数」92 条不同。原因：
- 列标题路径里时有时无地包含整表大标题“10/0.4kV干式配电变压器（单位：元/台）”；
- 型号后缀两次分别转录为 “MX3” 与 “NX3”（原件该字母印成实心墨块，像素上无法区分）；
- 名称按单元格分批交给模型生成，批次之间叫法不同。

**改动范围**：`main.py`（`_detect_matrix`、`_collect_matrix_rows`、清洗调用）、`pdf_extractor.py`（表头格的双读结果）。

**实现要求**：
1. 横跨全部价格列的表头行（整表大标题）不进入列标题路径，改为“表标题”单独保存，作为每条物料的一个参数（`表标题`）；单位仍从表标题中解析。
2. 列标题格本身有 `cell_issue`（例如两遍读成 MX3 / NX3）时，该列所有物料都要在待复核说明中注明“列标题识别存疑: …”。
3. 矩阵表**按列**清洗：每个价格列只调用一次模型，确定该列的物料名称；该列每个交叉格的参数由程序确定性生成（行标题、列标题各级、表标题），不再逐格交给模型。
4. 清洗调用 `temperature` 设为 0。

**验收**：
- 用 R1 `--repeat 2` 跑 S1：两次之间「名称规格」「厂家原始规格参数」「规格参数」差异为 0；若仍有差异，差异项必须全部带有“识别存疑”标注，并在回报中逐条说明。
- S1 价格门禁通过；模型调用次数下降（回报中给出前后对比）。
- 型号后缀在原件上无法区分 M/N 时，输出照转录结果，但必须带“列标题识别存疑”，**不得**自行改写为某一种。

## F6 双读比对忽略全角/半角差异（大脑发现）

**现象**：亮美聚规格原件为半角 `:` `;`，第一遍转录成全角 `：` `；`，第二遍为半角；双读把这种差异记为“参数两遍识别不一致”，造成误报。

**改动范围**：`pdf_extractor.py`（`_cross_check` 的比较函数）。

**实现要求**：
- 比较前对两边做 NFKC 归一并去掉空白；仅全半角/空白不同的视为一致；
- 输出值仍取第一遍原文，不做改写；
- 数字、字母、汉字本身不同的，仍记为不一致。

**验收**：
- S3 不再出现仅因标点全半角产生的“两遍识别不一致”；
- 单元测试：`"12：3"` vs `"12:3"` 一致；`"161000"` vs `"160000"` 不一致；`"NX3"` vs `"MX3"` 不一致。

## F7 结构化参数逐项核对原文出处（大脑发现）

**现象**：原文不是“键:值;”格式时，结构化参数由模型拆分生成，目前没有任何检查确认每个值确实出自原文，模型改写或补充的参数不会被发现。

**改动范围**：`main.py`（清洗结果处理处）。

**实现要求**：
- 对每条物料的每个参数值：做 NFKC、去空白、统一乘号（× x X * 视为同一字符）后，检查是否为该行原文（`raw_full_line`）归一化后的子串；
- 找不到出处的参数：保留在输出中，但在待复核说明中注明“参数无原文出处: 键=值”；
- 统计每份样例无出处参数的条数，写入运行日志。

**验收**：
- 单元测试：原文“功率48W 规格600×1200”，参数 `功率=48W` 有出处，`色温=4000K` 无出处并被标注；
- S1–S5 的回报中列出所有被标“无出处”的参数，并逐条对照原件判断：模型编造 / 原文确有但匹配规则没认出（后者要说明，交大脑决定是否放宽规则）。
