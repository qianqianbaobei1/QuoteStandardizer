## 四、用之前必须知道的四件事

1. **96% 的品名唯一对应一个类别**，但 **1,222 个品名是一对多**（歧义）。极端如「电线」对 9 个类别、「电力电缆」8 个。**不能压成一个**，必须保留分布，并配合"整表主业先验"（一级/二级）来选。
2. **支持度只认"去重企业数"，不要按行数加权**。只有 10%（2,840 个）品名有 ≥2 家企业印证；其余是单家自述。行数被电缆大户刷榜（天津市津成电线电缆 43,053 行、远东电缆 39,126 行）。
3. **归并轴有平台惯例**：同一个物料常有"材质轴 / 用途轴"两种归宿（例如「TPO耐根穿刺防水卷材」→ 材质轴 `TPO/TPV防水卷材`，不是用途轴 `耐根穿刺防水卷材`）。这份数据代表广材后台的惯例，和本项目现行规则不一定一致，冲突时要显式决定跟哪边。
4. **同名跨行业是本质性的**：「输入模块」在消防语境是 `消防器材/现场模块`，在报警系统语境是 `建筑智能化工程/报警系统模块`。所以查表必须带上下文。

## 五、怎么读它（给接手的人）

```bash
# 1) 直接看样本
head -20 data/广材分类词表_20261105/sample_first_2000.csv

# 2) 用现成的查表库（推荐，已按名称归一化 + 去重 + 带支持度）
sqlite3 category_lexicon.db "select * from lex_best where nk='电力电缆';"
sqlite3 category_lexicon.db "select t3, companies, rows from lex where nk='电线' order by companies desc;"

# 3) 从原始 CSV 重建查表库
python3 cli/build_category_lexicon.py \
  --csv "data/广材分类词表_20261105/result_广材后台数据库_db_op_gldjc_20261105084927.csv"
```

`category_lexicon.db` 表结构：

| 表/视图 | 内容 |
|---|---|
| `lex(nk, t1, t2, t3, rows, companies, sample)` | 一条 `(归一化品名, 类别)` 事实；`rows`=出现行数，`companies`=去重企业数，`sample`=原始写法样例 |
| `lex_best(nk, n_codes, t3_top, t1_top, t2_top, companies_top, rows_top)` | 每个品名的最优类别 + 歧义度（`n_codes>1` 即歧义） |
| `lex_meta(k, v)` | 来源文件名、sha256、行数统计 |

`nk` 的生成规则见 `name_norm.py`（去 `[572305]` 类别前缀 → 去型号前缀 `NLED4916` → 去括号补充 → NFKC → 去空白 → 小写）。
**建库与线上查表必须用同一个 `normalize_material_name()`，否则 key 对不上。**

## 六、已知质量情况（实测）

用本项目 `deliveries/` 下 161 家、134,672 行已有交付件做对账：

| 指标 | 数值 |
|---|---|
| 品名精确命中词表 | 9,016 行（6.7%） |
| 命中行中与交付件编码一致 | 7,865 行（87.2%） |
| 命中但不一致 | 1,151 行，其中跨大类 720 行（多数是交付件的系统性问题，例如「双电源自动转换开关」交付件给 `工程检测仪器仪表/电源`，词表给 `电气设备及附件/配电开关`） |

覆盖率只有 6.7%，是因为报价单里的品名与广材商品名是两群人的用词；要吃到剩下 93%，必须做模糊/向量召回，不能只靠精确查表。
